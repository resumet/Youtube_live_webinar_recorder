# 구현 계획 및 수용 기준 추적

PRD 1.0(2026-10-19)을 기준으로 한다. 단계 완료 시 테스트 후 별도 Git 커밋과 push를 수행한다.
현재 기준선은 1단계이며, 표에서 후속 단계로 표시한 기능은 아직 구현되지 않았다.

## 구조

```text
src/youtube_live_recorder/
  main.py                 CLI 진입점 (3단계에서 GUI 진입점 추가)
  bootstrap.py            경로·로그·DB·설정 조립
  config.py               고정 주기 및 저장 설정
  core/state_machine.py   방송/세션 상태 전이
  data/                   모델·마이그레이션·DB·저장소
  services/interfaces.py  메타데이터·녹화·검사 계약
  utils/                  URL·시각·경로·오류·로그
tests/unit/               네트워크 없는 로직/DB 테스트
tests/integration/        별도 프로세스 실행·재시작 테스트
scripts/                  개발 환경 재현
docs/                     PRD·계획·결정·실행 증거
```

UI, 아이콘, 패키징 파일은 구현 단계에 실제 내용과 함께 추가한다.

## 단계별 산출물

| 단계 | 범위 | 완료 판정 |
|---|---|---|
| 1 | 초기화, 데이터, URL/상태 머신, 서비스 계약 | 초기화·중복·경쟁·재시작 테스트 및 Windows CLI 실행 |
| 2 | 메타데이터, 폴링, 녹화 프로세스, 중지, MP4 검사 | 모의 방송 상태 전이 + FFmpeg 생성 로컬 스트림 + 실제 프로세스 중지 검증. 이 검증 후 GUI 착수 |
| 3 | 한국어 PySide6, 대시보드/대기/기록/설정, 트레이/알림 | Qt 스모크·스레드 응답성·Windows 수동 점검 |
| 4 | 재연결, 충돌 복구, 다시보기, 디스크, 전원 | 장애 주입·벽시계 만료·세그먼트 보존·재시작 테스트 |
| 5 | 번들, 설치/제거, 긴 방송 검증 | pytest 및 패키징 검사 후 실제 Setup.exe 산출; 미검증 항목 별도 명시 |

## 엔진 우선 검증 순서

1. 예약→라이브, 두 방송 동시 라이브, 단일 오류를 종료로 오판하지 않는 모의 응답.
2. 실제 yt-dlp CLI의 옵션 지원/JSON 계약 확인; 사용자 설정 파일의 쿠키·플러그인 개입 차단.
3. 로컬에서 생성한 영상+음성 스트림을 저장하고 FFprobe 검사. 실제 YouTube 지원 검증과 구분.
4. 중지→정리→검사와 프로세스 트리 종료 확인. Windows에서는 숨겨진 콘솔/제어 신호 차이 검증.
5. 허가받은 실제 YouTube 테스트 방송으로 DVR 가능·불가, 화질 폴백 및 방송 종료 검증.
6. 모의/로컬 엔진 게이트 통과 후 GUI 연결. 실제 방송이 없으면 실서비스 검증은 미완료로 유지.
