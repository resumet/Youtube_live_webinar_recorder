# 구현 계획 및 수용 기준 추적

PRD 1.0(2026-10-19)을 기준으로 한다. 단계 완료 시 테스트 후 별도 Git 커밋과 push를 수행한다.
v0.1 개발·Windows 11 설치 검증을 완료했고, 추가 요청에 따른 v0.2 동시 녹화를 구현했다.
기본 5개, 설정 1~10개, 진행 중 개별 중지, 새 녹화에 적용되는 저장 폴더 변경을 지원한다.
전체 175개 테스트와 v0.2 Windows 번들 검증을 통과했고 Setup.exe를 생성했다.
기존 설치본과 녹화 워커가 사용 중이어서 새 설치·재설치·제거 시험은 별도 환경에서 수행해야 한다.
v0.2.1에는 진행 중인 녹화의 실제 저장 폴더 및 지정한 구글 드라이브 폴더 열기를 추가했다.
전체 175개 테스트, 새 번들의 미디어 검사와 Windows 네 배율 화면 검사를 통과했다.
아래 1단계 추적 표는 최초 구현 기록이며 이후 변경 내용은 하단에 보완한다.

## 구조

```text
src/youtube_live_recorder/
  main.py                 CLI 및 GUI 진입점
  bootstrap.py            경로·로그·DB·설정 조립
  config.py               고정 주기 및 저장 설정
  core/state_machine.py   방송/세션 상태 전이
  data/                   모델·마이그레이션·DB·저장소
  services/interfaces.py  메타데이터·녹화·검사 계약
  utils/                  URL·시각·경로·오류·로그
tests/unit/               네트워크 없는 로직/DB 테스트
tests/integration/        별도 프로세스 실행·재시작 테스트
scripts/                  개발 환경 재현
docs/                     PRD·계획·결정·실행 증거
```

`ui/`는 화면·컨트롤러·트레이 알림, `packaging/`은 PyInstaller·Inno Setup 설정을 포함한다.

## 엔진 우선 검증 순서

1. 예약→라이브, 두 방송 동시 라이브, 단일 오류를 종료로 오판하지 않는 모의 응답.
2. 실제 yt-dlp CLI의 옵션 지원/JSON 계약 확인; 사용자 설정 파일의 쿠키·플러그인 개입 차단.
3. 로컬에서 생성한 영상+음성 스트림을 저장하고 FFprobe 검사. 실제 YouTube 지원 검증과 구분.
4. 중지→정리→검사와 프로세스 트리 종료 확인. Windows에서는 숨겨진 콘솔/제어 신호 차이 검증.
5. 허가받은 실제 YouTube 테스트 방송으로 DVR 가능·불가, 화질 폴백 및 방송 종료 검증.
6. 모의/로컬 엔진 게이트 통과 후 GUI 연결. 실제 방송이 없으면 실서비스 검증은 미완료로 유지.

## 2단계 반영

- FR-03: `inspect` 메타데이터 조회 및 `watch` 감지 시 DB 갱신. GUI 등록 전 미리보기는 3단계.
- FR-05~08: 60초 감지, 조회 오류 백오프·jitter, 단일 슬롯, 동시 시작 우선권 및 건너뜀,
  화질 상한·낮은 화질 폴백을 구현했다. 놓친 방송의 다시보기 처리는 4단계.
- FR-09~12: yt-dlp 백그라운드 프로세스, DVR 시도/형식 미지원 폴백, 안전한 중지,
  FFmpeg remux, FFprobe 검사, 파일·DB 완료 상태 연결을 구현했다.
- FR-17~19: 저장 시작 전 권한/여유 공간, 서울 날짜 파일명, Windows 이름 정규화 및 충돌 방지.
- FR-23/30: 완료 항목 목록 제외, 부분/실패 기록, 도구 오류 분류.
- FR-13/14/15/16/27/28/32의 재연결·충돌 후 파일 복구·다시보기·녹화 중 디스크 감시·전원 제어는 남아 있다.
- Windows 프로세스 Job Object와 엔진 인스턴스 잠금을 구현했다. 앱 강제 종료 시 자식 프로세스가
  종료되는 것과, 다음 실행에서 임시 파일을 복구하는 것은 별개이며 후자는 아직 미구현이다.

## 3단계 반영

- FR-03/04: 메타데이터·썸네일 미리보기, 권한 확인 등록, 중복 오류, 대기 화질/파일명 수정 및 취소.
- FR-17/20~26: 한국어 4개 화면, 폴더 선택, 실시간 상태·실제 화질·경과 시간·저장량,
  기록 파일/폴더 열기, 트레이 숨김·복원·완전 종료, 상태별 아이콘과 시작/완료 알림.
- 네트워크·DB·폴더 검사는 작업 스레드에서 실행한다. 늦게 도착한 이전 URL 조회 결과는 버린다.
- 종료 요청 시 새 녹화를 차단하고 백그라운드에서 진행 파일을 정리한다.
- Windows Known Folder API로 이동된 동영상 폴더를 따른다.
- Qt 자동화·화면 렌더링은 확인했다. Windows 알림 센터의 실제 팝업/클릭과 배율별 화면은
  수동 검증이 남아 있다. 업데이트 버튼은 현재 배포 미준비 안내만 제공한다.

## 4단계 반영

- FR-13: 최대 6회 재연결, 15초부터 지수 백오프+jitter, 세그먼트별 MP4와 원본 보존,
  연결 중단 시 부분 저장 표시 및 다시보기 전환. 한도를 넘긴 방송을 즉시 다시 시작하지 않는다.
- FR-14/32: 앱 인스턴스 잠금 획득 뒤 미완료·실패 파일 검사, 부분 MP4 복구, DB 슬롯 정리,
  대기 목록 재검증 및 진행 중인 방송 재개. 복구 도중 다시 충돌한 상태도 재진입한다.
- FR-15/16: DB에 저장된 다시보기 확인 시각·종료 관찰 기준 24시간 기한, 30분 간격,
  기존 라이브 보존, 라이브 시작 시 진행 중인 다시보기 중단·대기 전환.
- FR-27: 시작 전/중간 저장소 검사 및 remux용 추가 공간 검사. 부족 시 오류 안내·부분 파일 보존.
- FR-28: 엔진 스레드에서 Windows 시스템 절전만 방지하고 파일 정리가 끝난 뒤 해제.
- 사용자 중지와 앱 완전 종료를 구분한다. 전자는 자동 재시작하지 않고, 후자는 다음 실행에서 재검증한다.
- Windows 전원 API와 실제 파일을 이용한 프로세스 충돌 복구를 검증했다. 실제 네트워크 장치
  끊김/재연결, 장시간 무인 실행, 절전 시간 경과의 실제 관찰은 아직 검증하지 않았다.

## 5단계 반영 및 Windows 11 검증

- FR-29: HTTPS 매니페스트 조회, 새 버전 알림, 사용자 요청 다운로드와 SHA256 검사,
  별도 설치 확인 및 녹화 슬롯과 원자적인 설치 차단을 구현했다. 실제 배포 URL은 비어 있다.
- PyInstaller 폴더형 패키지: 창 전용 GUI와 숨겨진 콘솔 워커를 분리하고 같은 라이브러리를 공유한다.
  FFmpeg/FFprobe/Deno, Python/Qt, EJS와 라이선스를 포함한다.
- 시스템 PATH에서 개발 도구를 제외한 상태로 번들 진단·미디어 파이프라인·GUI 응답/종료를 검증했다.
- Inno Setup 7.1.0 컴파일러를 해시/게시자 서명으로 검증하고 Setup.exe를 생성했다.
  실행 중 설치 차단과 실제 설치·설치본 실행·재설치·제거, DB·설정·별도 파일 보존을 확인했다.
- AC-20용 실시간 자체 생성 스트림으로 실제 3시간 시험을 통과했다. 최대 UI 간격은 0.192초,
  완성 MP4는 10,800.064초이며 FFprobe 검사와 정상 종료를 확인했다. 실제 YouTube 장시간 시험과 구분한다.
- 100/125/150/200% Qt 배율과 Windows 11 사용자의 트레이 복원을 확인했다. 완료 알림으로
  정확한 시험 영상이 있는 폴더가 열린 것도 사용자 수동 확인을 통과했다. 해당 실행의 클릭 이벤트
  미기록 원인은 미확인이다. 설치본의 셸 클릭, Windows 10, 물리적 다중 모니터 이동,
  실제 YouTube 자연 종료/장시간 및 절전 타이머 만료 동작은 미검증이다.
- 단계별 로컬 커밋을 보존했다. GitHub 연결 계정의 저장소 쓰기 권한이 없어 원격 업로드는 남아 있다.
