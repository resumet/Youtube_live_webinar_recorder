# 단계별 검증 기록

## 1단계 · 2026-10-19 (Asia/Seoul)

Windows 작업 공간에서 프로젝트 전용 CPython 3.13.16을 사용했다.
PySide6 6.12.0, yt-dlp 2026.8.19가 설치되었으며 Qt import와 yt-dlp 버전 실행을 확인했다.

자동화 테스트: **60개 통과**. Ruff 정적 검사 및 27개 Python 파일 포맷 검사를 통과했다.
CLI `init`와 `diagnose`를 Windows에서 실행하여 DB 스키마 1과 기본 무결성 검사 통과를 확인했다.
현재 FFmpeg/FFprobe/Deno는 아직 설치하지 않았고 시스템 Node 경로는 탐지되었다.

준비 스크립트 실행에서 Windows PowerShell 5의 UTF-8 BOM 없는 한글 메시지와
파이프 출력의 CP949 문제가 드러나, `.ps1`을 UTF-8 BOM으로 저장하고 CLI 출력은 UTF-8로
명시했다. uv의 Python 전역 레지스트리·실행 링크 등록은 준비 스크립트에서 비활성화했다.

검증 내용:

- 대표 URL 3종과 모바일·추가 query 정규화, 유사 도메인/사용자 정보/잘못된 ID 차단.
- DB 생성, WAL·외래키, 반복 초기화, 트랜잭션 롤백, 실패한 마이그레이션 원자성.
- 동시 등록 8건 중 1건만 성공, 동시 슬롯 요청 2건 중 1건만 성공.
- 활성 세션 취소로 슬롯이 사라지지 않는지, 파일 검사 없이 성공 기록이 가능한지 확인.
- 별도 Python 프로세스에서 등록 후 재실행하여 목록 복원 및 중복 차단.
- UTC 저장과 서울 날짜 경계, 한국어 로그, URL 및 예외 traceback 마스킹.

아직 검증하지 않은 것:

- 실제 YouTube 메타데이터/라이브/DVR/다시보기 및 서비스 접근 제한 응답.
- FFmpeg 녹화·프로세스 중지·FFprobe 검사, 재연결과 충돌 후 파일 복구.
- GUI·트레이·Windows 알림 클릭·절전 방지·3시간 방송.
- PyInstaller 산출물·Inno Setup 설치/제거. **Setup.exe는 아직 없음.**

## 2단계 · 2026-10-19 (Asia/Seoul)

최종 자동화 검사: **104개 통과 (26.43초)**. Ruff 정적 검사와 47개 Python 파일 포맷 검사 통과.
CLI `init`/`diagnose` 실행에서 스키마 2 마이그레이션, DB 기본 검사, 설치된 도구 경로를 확인했다.

FFmpeg/FFprobe와 Deno를 해시 검증하여 설치했다. 실제 Windows 환경에서 다음을 검증했다.

| 검증 | 결과 |
|---|---|
| 제공된 허가 방송 메타데이터 | `is_live` 및 방송 시작 시각 조회 성공. 테스트 URL·제목은 공개 기록에서 제외 |
| 현재 시점 라이브, 약 20초 후 수동 중지 | 720p H.264 + AAC, 22.133333초, 5,306,528바이트 MP4, FFprobe 통과 |
| `--live-from-start`, 약 20초 후 수동 중지 | 720p H.264 + AAC, 585.816009초, 32,244,082바이트 MP4, FFprobe 통과 |
| 정상 중지 신호 | Python 자식과 FFmpeg 자식 모두 강제 종료 없이 중지 |
| 신호를 무시하는 자식 | 유예 시간 후 Job Object 종료, 자식 잔존 없음 |
| 부모 강제 종료 | 별도 부모 프로세스를 강제 종료한 뒤 자식 프로세스 종료 확인 |
| 엔진 중복 실행 | 같은 데이터 폴더 잠금으로 두 번째 프로세스 거부, 첫 프로세스 종료 후 재획득 |
| 로컬 전체 경로 | 자동 감지 fixture → 실제 yt-dlp HTTP 다운로드 → 실제 FFmpeg remux → FFprobe → DB COMPLETE |

DVR 출력은 다운로드된 과거 구간이 재생 가능한 MP4임을 확인한 것이다. 방송 전체 시작점을
정확히 확보했는지, 중간 구간이 모두 존재하는지 검증한 결과로 해석하면 안 된다.
위 실제 방송 시험은 어댑터 경로를 실행했고, 스케줄러·DB까지 포함한 추가 실서비스 시험은
자동 승인 검토 서비스의 용량 오류로 실행되지 않았다. 동일 경로의 로컬 통합 테스트는 통과했다.

자동 테스트는 네트워크 조회 실패, 60초 간격, 동시 시작·슬롯 경쟁, 부분 저장,
종료 두 번 확인, 검사 실패, 실제 yt-dlp 화질 선택기, 원본·충돌 파일 보존을 포함한다.
순수 단위 테스트 외 미디어 통합 테스트는 고정 FFmpeg/FFprobe를 필요로 하므로 도구가 없으면 실패한다.

남은 실제 검증: 실제 방송의 자연 종료, 서비스/네트워크 장애 주입, 긴 방송, GUI·알림·전원,
설치/제거. 녹화 파일과 테스트 방송 URL은 `.runtime/`에만 저장하며 Git에 포함하지 않는다.

## 3단계 · 2026-10-19 (Asia/Seoul)

GUI 연결 후 전체 테스트 **111개 통과 (28.77초)**. 종료/오류 표시/화질 콜백 테스트를 추가한 뒤

- 느린 메타데이터 응답 중 UI 타이머와 메뉴가 동작하고 이전 URL 결과를 무시함을 확인했다.
- 시작 오류 안내가 종료 메시지에 덮이지 않고, 종료 도중 새 녹화가 시작되지 않음을 확인했다.

  프로필의 실제 경로 변경 테스트는 수행하지 않았다.

Windows 알림 센터의 팝업/클릭, 실제 사용자 세션 트레이 및 다중 DPI/모니터 수동 검증은 남아 있다.
재연결·복구·다시보기·녹화 중 디스크·절전 방지는 4단계, 업데이트·설치 파일은 5단계 작업이다.

CLI `diagnose`에서 DB 스키마 3과 무결성 검사, 번들 개발 도구 경로를 확인했다.

| 검증 | 결과 |

때까지의 관찰은 수행하지 않았다. 장시간 방송과 Windows 알림 센터 수동 클릭은 미검증이다.

제공된 허가 방송을 최신 전체 엔진으로 다시 시험하는 명령은 자동 승인 검토 서비스의 모델 용량
오류로 실행되지 않았다. 2단계의 실제 라이브 결과를 4단계 전체 엔진 실서비스 검증으로 대체하지 않는다.
Git 커밋도 같은 검토 서비스 오류로 대기 중이며, 2·3·4단계 소스는 각각 로컬 스냅샷으로 보존한다.
GitHub 연결 권한 재조회 결과 `push=false`; 계정 변경 후 업로드 재시도가 필요하다.

패키징·업데이트 구현 후 전체 자동화 테스트 **153개 통과 (61.74초)**.
Ruff 정적 검사 통과. 설치 검사 스크립트 추가 전 77개 Python 파일 포맷 검사도 통과했다.

| 검증 | 결과 |
|---|---|
| PyInstaller GUI/워커 | 별도 실행 파일과 공유 `_internal` 빌드 성공 |
| Python 없는 실행 환경 가정 | PATH에서 개발 도구를 제외하고 번들 FFmpeg/FFprobe/Deno로 진단·자체 시험 통과 |

| 번들 GUI | offscreen 및 실제 Windows qwindows 플러그인에서 한글 렌더링, 엔진 시작, 타이머 응답 및 정상 종료 통과 |

| 짧은 soak 명령 점검 | 자체 생성 5초 영상, COMPLETE/FFprobe 통과, 최대 UI 간격 0.124초 미만, 정상 종료 |

FFmpeg 오류 출력의 구체적인 문구는 yt-dlp quiet 모드에서 생략될 수 있으므로 네트워크 시험은
연결 여부, 경과 시간, 실제 비정상 반환, 외부 timeout/강제 종료가 없는지 확인했다.
Windows Job Object의 강제 종료 코드는 0일 수 있어 `forced` 상태를 별도로 판단한다.

3시간 시험은 14:08(KST)에 최신 번들로 시작했으며 아직 완료되지 않았다.
처음 7분 동안 UI 타이머 최대 간격 0.126초 미만을 관찰했다. 이것은 중간 관찰값이다.
짧은 soak 시험이나 3시간 길이 파일의 빠른 생성은
AC-20 통과 근거가 아니다. 전체 실행 시간·메모리 표본·UI 간격·최종 MP4를 별도로 기록한다.
실제 YouTube 자연 종료/긴 방송, Windows 10, 알림 센터 수동 클릭, 다중 DPI는 여전히 미검증이다.

공식 컴파일러 준비는 처음에 자동 승인 검토 서비스의 시간 초과/모델 용량 부족으로 실행되지
않았으나, 서비스가 다시 응답한 후 재시도에 성공했다. 고정 SHA256과 게시자 서명을 확인한
Inno Setup 7.1.0으로 **Setup.exe를 생성했다.**

- 첫 설치 파일: `dist/installer/YouTubeLiveRecorder-0.1.0-Setup.exe`, **181,194,864바이트**.
- 첫 설치 파일 SHA256: `d5a013a1af3de04c6d4ffd00b04325fb210c462a9102c231cd7dabe95382b33c`.
- 3시간 시험이 실행 중인 상태에서 실제 설치 파일을 실행해 `AppMutex`에 따른 설치 차단을 확인했다.
  반환 코드 1, 설치 폴더/제품 등록 생성 없음. 설치 로그에 한국어 실행 중 안내가 남았다.
- 앱 종료 후 설치·재설치·제거와 사용자 데이터 보존 시험은 아직 미검증이다.
- 코드 서명 인증서/실제 업데이트 서버는 구성하지 않았다. 현재 설치 파일은 서명되지 않았다.

승인 서비스 복구 후 제공된 허가 방송으로 최신 **소스 엔진 전체 경로**를 실행했다.
자동 감지 → LIVE 녹화 → 20초 뒤 사용자 중지 → 720p MP4 기본 검사 → DB PARTIAL/CANCELLED,
슬롯 해제까지 성공했다. 파일은 **519.801678초, 37,458,376바이트**이며 DVR로 확보된 부분 구간이다.
전체 방송 시작점/완전성을 증명하지 않는다.

이후 **번들 실행 파일의 추가 실방송 시험**은 조회가 45초 중지 시점까지 완료되지 않아 녹화
