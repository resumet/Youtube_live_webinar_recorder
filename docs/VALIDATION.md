# 단계별 검증 기록

## 1단계 · 2026-10-19 (Asia/Seoul)

Windows 작업 공간에서 프로젝트 전용 CPython 3.13.16을 사용했다.
PySide6 6.12.0, yt-dlp 2026.8.19가 설치되었으며 Qt import와 yt-dlp 버전 실행을 확인했다.

자동화 테스트: **60개 통과**. Ruff 정적 검사 및 27개 Python 파일 포맷 검사를 통과했다.
CLI `init`와 `diagnose`를 Windows에서 실행하여 DB 스키마 1과 기본 무결성 검사 통과를 확인했다.
현재 FFmpeg/FFprobe/Deno는 아직 설치하지 않았고 시스템 Node 경로는 탐지되었다.

준비 스크립트 실행에서 Windows PowerShell 5의 UTF-8 BOM 없는 한글 메시지와
파이프 출력의 CP949 문제가 드러나, `.ps1`을 UTF-8 BOM으로 저장하고 CLI 출력은 UTF-8로
명시했다. uv의 Python 전역 레지스트리·실행 링크 등록은 준비 스크립트에서 비활성화했다.

검증 내용:

- 대표 URL 3종과 모바일·추가 query 정규화, 유사 도메인/사용자 정보/잘못된 ID 차단.
- DB 생성, WAL·외래키, 반복 초기화, 트랜잭션 롤백, 실패한 마이그레이션 원자성.
- 동시 등록 8건 중 1건만 성공, 동시 슬롯 요청 2건 중 1건만 성공.
- 활성 세션 취소로 슬롯이 사라지지 않는지, 파일 검사 없이 성공 기록이 가능한지 확인.
- 별도 Python 프로세스에서 등록 후 재실행하여 목록 복원 및 중복 차단.
- UTC 저장과 서울 날짜 경계, 한국어 로그, URL 및 예외 traceback 마스킹.

아직 검증하지 않은 것:

- 실제 YouTube 메타데이터/라이브/DVR/다시보기 및 서비스 접근 제한 응답.
- FFmpeg 녹화·프로세스 중지·FFprobe 검사, 재연결과 충돌 후 파일 복구.
- GUI·트레이·Windows 알림 클릭·절전 방지·3시간 방송.
- PyInstaller 산출물·Inno Setup 설치/제거. **Setup.exe는 아직 없음.**

## 2단계 · 2026-10-19 (Asia/Seoul)

최종 자동화 검사: **104개 통과 (26.43초)**. Ruff 정적 검사와 47개 Python 파일 포맷 검사 통과.
CLI `init`/`diagnose` 실행에서 스키마 2 마이그레이션, DB 기본 검사, 설치된 도구 경로를 확인했다.

FFmpeg/FFprobe와 Deno를 해시 검증하여 설치했다. 실제 Windows 환경에서 다음을 검증했다.

| 검증 | 결과 |
|---|---|
| 제공된 허가 방송 메타데이터 | `is_live` 및 방송 시작 시각 조회 성공. 테스트 URL·제목은 공개 기록에서 제외 |
| 현재 시점 라이브, 약 20초 후 수동 중지 | 720p H.264 + AAC, 22.133333초, 5,306,528바이트 MP4, FFprobe 통과 |
| `--live-from-start`, 약 20초 후 수동 중지 | 720p H.264 + AAC, 585.816009초, 32,244,082바이트 MP4, FFprobe 통과 |
| 정상 중지 신호 | Python 자식과 FFmpeg 자식 모두 강제 종료 없이 중지 |
| 신호를 무시하는 자식 | 유예 시간 후 Job Object 종료, 자식 잔존 없음 |
| 부모 강제 종료 | 별도 부모 프로세스를 강제 종료한 뒤 자식 프로세스 종료 확인 |
| 엔진 중복 실행 | 같은 데이터 폴더 잠금으로 두 번째 프로세스 거부, 첫 프로세스 종료 후 재획득 |
| 로컬 전체 경로 | 자동 감지 fixture → 실제 yt-dlp HTTP 다운로드 → 실제 FFmpeg remux → FFprobe → DB COMPLETE |

DVR 출력은 다운로드된 과거 구간이 재생 가능한 MP4임을 확인한 것이다. 방송 전체 시작점을
정확히 확보했는지, 중간 구간이 모두 존재하는지 검증한 결과로 해석하면 안 된다.
위 실제 방송 시험은 어댑터 경로를 실행했고, 스케줄러·DB까지 포함한 추가 실서비스 시험은
자동 승인 검토 서비스의 용량 오류로 실행되지 않았다. 동일 경로의 로컬 통합 테스트는 통과했다.

자동 테스트는 네트워크 조회 실패, 60초 간격, 동시 시작·슬롯 경쟁, 부분 저장,
종료 두 번 확인, 검사 실패, 실제 yt-dlp 화질 선택기, 원본·충돌 파일 보존을 포함한다.
순수 단위 테스트 외 미디어 통합 테스트는 고정 FFmpeg/FFprobe를 필요로 하므로 도구가 없으면 실패한다.

남은 실제 검증: 실제 방송의 자연 종료, 서비스/네트워크 장애 주입, 긴 방송, GUI·알림·전원,
설치/제거. 녹화 파일과 테스트 방송 URL은 `.runtime/`에만 저장하며 Git에 포함하지 않는다.
